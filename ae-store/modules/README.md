# Modules

Proposed classes: widgets, skills, harnesses and capability adapters.

A future published module must identify its immutable source/artifact, license, compatibility, requested permissions, input/output contracts, data destinations, resource/cost limits, publisher provenance and verification evidence. Reject mutable or unresolved artifacts at binding time.

No modules are installed here. A module's declaration or registry presence grants no runtime permission. Open-source application code and proprietary model/API services must be labeled separately.
